# UI Design

## 竖屏视口

MathGame 的逻辑视口是：

```text
width:  320
height: 640
ratio:  1:2
```

这是既有横屏项目 `640 × 320` 的方向反转。所有主要页面先在这个逻辑尺寸下完成，再由最外层 `GameViewport` 根据设备可用区域整体等比缩放。

## 缩放规则

```text
scale = min(availableWidth / 320, availableHeight / 640)
```

- 保持 1:2 比例，不拉伸。
- 宽屏桌面环境居中展示，外围使用中性背景。
- 手机较矮或较窄时整体缩小，不能裁掉数字键或功能按钮。
- 浏览器地址栏变化、横竖屏变化和 `visualViewport` resize 时重新计算。
- Android 正式工程锁定 portrait；Web 端横屏时仍居中展示竖屏画布。

## 安全区域

320×640 表示游戏内容基线，不表示可以忽略刘海和手势区。Android 接入时需要确认状态栏策略：

- 如果内容不延伸到系统栏，WebView 可用区域本身就是缩放边界。
- 如果使用 edge-to-edge，则在外层读取 `safe-area-inset-*` 后再计算可用区域。
- 棋盘、数字键和返回按钮不能落入系统手势热区。

第一版优先采用“不覆盖系统栏”的稳妥方案。

## 数独页面建议分区

以 320×640 为基准：

```text
顶部导航与标题
难度 / 错误 / 计时信息
306 × 306 棋盘
操作栏：撤销、擦除、笔记、提示
1～9 数字键
底部安全留白
```

棋盘建议使用 306×306，使每个格子在逻辑尺寸下恰好是 34×34；左右各留 7px。最终尺寸可以在真机手感测试后微调，但必须保证九宫粗线和格线清晰。

## 棋盘状态视觉

视觉层必须能区分：

- 题目预设数字
- 用户正确输入
- 用户错误输入
- 当前选中格
- 同行、同列、同宫关联区域
- 全盘相同数字
- 提示目标格
- 提示排除位置
- 多候选笔记

不能只依赖颜色表达错误或选中状态，需要同时使用字重、边框、符号或动画，照顾色觉差异。

## 算术填字地图

算术填字统一使用 `14×14` 细网格，不套用数独的正方形棋盘视觉。路线由随机衔接点之间的短直线连接形成不规则连通支流，孤岛和未连接位置显示为禁用格；四档难度只改变支流数量、知识点和待填卡牌数量，不切回方阵模板。

地图状态必须同时依靠颜色和形状区分：固定数字使用暖黄实体格，待填格使用白底青色虚线，玩家输入使用深青底白字，变量使用紫色标识，禁用格不表现为可点击空格。符号也是路线上的实体格，并可成为卡牌目标。已放卡牌保留身份位置，同时用降低对比、虚线、对勾和“已放”提示其状态。

交互顺序是“先点卡牌，再点同类型空格”，不支持拖动。横向关系从左向右读，竖向关系从上向下读；每条支流先找到关系符，再比较左/上侧与右/下侧。两侧内部都严格按版面顺序解析，`+ − × ÷` 一律不倒读、不交换操作数。竖向的 `> < ≥ ≤` 在棋盘中旋转为上下朝向，开口朝较大的一侧、尖端朝较小的一侧；牌池仍显示未旋转的标准符号。不同关系不能沿同一直线拼成含多个关系符的假长式。填满前不显示关系错误；填满后若有错误，红色标出冲突支流并把其中的玩家卡牌退回牌池。当前摆法无法延伸时，提示可以搬回放错位置的已用牌。困难档变量统一写作 `a、b、c`，乘法始终使用 `×`。

## 格点建筑师地图

格点建筑师按难度使用 `5×5` 至 `8×8` 单位格地图。空地使用浅色细网格，已建造格使用绿色实体面，障碍同时使用灰色、虚线和岩石形状，地标使用黄色星标；给定对称轴以虚线贯穿地图，中心对称点使用独立圆点。相邻建造格共享边不重复描边，只在区域外缘自动绘制清晰边界。

交互是点击单位格建造、再次点击拆除，不依赖拖动。地图使用原生按钮和完整的行列 ARIA 名称，键盘也能逐格操作。普通与困难档仍保留面积、周长的当前测量值，但只在玩家点击“检查方案”后把未满足条件标成冲突；不得把玩家图形与隐藏 witness 逐格比较。

条件卡使用文字、图标和状态共同区分“待检查、已满足、冲突”。错误时高亮能明确定位的断开、洞口、缺失地标或非对称格；面积和周长只展示当前值与目标。结算页继续展示玩家实际完成的建筑图，题号、用时、调整次数和提示次数保持在 `320×640` 内可截屏。

## 触控规则

- 常用触控目标不小于 40×40 逻辑像素。
- 数字键必须允许连续快速输入，不能依赖 hover。
- 笔记模式要有持续可见的开启状态，不能只靠一次 toast。
- 明显冲突时先拒绝落笔，再触发短振动和局部视觉反馈。
- 所有动画都要尊重 `prefers-reduced-motion`。
- 浏览器长按选择、双击缩放和页面滚动不能干扰棋盘操作。

## 视觉方向

MathGame 应有自己的安静、清晰、适合长时间思考的视觉语言。可以借鉴其他数独应用的信息层级和交互结果，但不复制其插画、图标、颜色组合或整体皮肤。

当前 Web UI 沿用暖色纸张、青绿色强调色和低噪声圆形装饰；游戏页参考用户提供的界面层级，使用浅蓝背景、白色控制面板和深色棋盘线，但不复制来源应用的图标、素材或完整皮肤。

## 当前页面流程

```text
首页 ⇄ 每日任务日历 ⇄ 我的
  ↓
选择游戏
  ├→ 数独：难度或种子 → 唯一解生成 → 输入 / 笔记 / 提示
  ├→ 算术填字：四档难度或种子 → 支流地图与至少一解检查 → 放置卡牌
  └→ 格点建筑师：四档难度或题号 → 几何地图与至少一解检查 → 点按建造
  → 结算 → 复制题目编号
```

首页、日历与“我的”是应用一级页面，共用底部浮动导航；进入难度、生成、游戏和结算后隐藏，避免占用玩法空间。导航保持至少 40×40 的触控目标，使用同一套圆润半实心 SVG 图标，并通过文字、颜色和 `aria-current` 共同表达当前页。

日历页默认选中今天，顶部任务卡展示所选日期可选择的游戏。玩家直接点击数独、算术填字或格点建筑师中的任意一项；完整完成所选游戏后，结算页明确显示“打卡成功”或“补签成功”，对应日期才切换为完成，其他项目显示“本次未选择”。已完成日期仍可选择查看，状态分别显示“已打卡”或“已补签”；未来日期不可选择。日期按钮保持 40×40，并用金色描边标识当前选择，打卡日期使用青绿色卡片和对勾，补签额外显示“补签”。当月所有日期全部完成后才解锁全勤奖杯；未全勤时奖杯保持未解锁状态，图标按当月完成天数从下往上逐步由灰色填为金色，解锁后再按当月补签次数显示完整的金、银或铜色。

奖杯卡展示当月签到进度和补签次数，整月每天都完成后才正式点亮。奖杯等级按实际完成的补签任务天数计算：0–4 次为金色、5–14 次为银色、15 次及以上为铜色。补签游戏按真实完成局数和用时记录，不生成无游戏成绩的空补签。日历固定为周一开头的 6 行网格，避免月份变化造成页面跳动。

“我的”页面只包含本地身份提示、累计打卡/局数/连续天数/全勤奖杯统计和隐私说明，不承载单个游戏的开局入口。

数独难度选择页在三档普通入口下提供“按种子进入”。输入框支持粘贴、大小写归一和清空；完整种子包含难度与 seed，非法输入在卡片内反馈，有未完成存档时需要二次确认才替换。

游戏页顶部常驻显示可复制题号，方便直接报告具体题面。结算页点亮并展示玩家实际完成的棋盘，把题目编号放在独立卡片中并提供复制按钮；成功后切换为对勾和“已复制”，失败时提示长按编号手动复制。完成棋盘、统计、题号、“再来一局”和“返回主页”必须在 `320×640` 内同屏可见，便于直接截屏。

复杂组件可以在开发环境的 `/?preview=1` 独立查看。预览入口不进入生产玩家流程。
