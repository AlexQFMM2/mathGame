# Profile, Daily Tasks and Puzzle Challenge Plan

## 目标

把当前“完成任意一局即打卡”升级为可扩展的每日任务：每个已上线游戏类型各有一条任务，当天全部完成才算打卡成功。同时在结算页提供题目种子复制能力，并在数独难度选择页通过种子复现同一道数独。

## 范围

### 题目编号

- [x] 结算页将题目编号展示为可点击复制的独立控件。
- [x] 复制操作提供成功、失败和不支持状态反馈，不静默失败。
- [x] 数独核心提供严格的编号解析函数，编号必须能还原难度与 seed。
- [x] 输入合法编号后重新生成完全相同的题面和答案，并作为正常可保存游戏开始。
- [x] 输入接受大小写和首尾空格，非法、未知游戏或超范围 seed 给出明确提示。

### 每日任务与打卡

- [x] 每个 `GAME_CATALOG` 中已上线的游戏类型每天对应一条任务。
- [x] 完成某游戏一局后，该游戏当天任务完成；继续游玩仍累计局数和最佳用时。
- [x] 点击“打卡”进入今日任务游戏，只有完成游戏后才完成任务并签到成功。
- [x] 日历页能查看当天任务完成数，并明确表达“全部任务完成才打卡”。
- [x] 当前只有数独上线，因此完成一局数独即完成 `1 / 1`，但模型不能写死为数独专属聚合结构。
- [x] 点击过去日期只切换顶部任务详情；再点“补签”进入任务游戏，完成后才写入真实游戏成绩和补签。
- [x] 今天使用“打卡”，过去使用“补签”；未来日期不可选，已完成日期只显示完成状态。
- [x] 签到任务目标日期和模式独立持久化，中途退出或刷新后继续游戏仍归属原日期。
- [x] 月度全勤奖杯按补签次数分级：0–4 次金色、5–14 次银色、15 次及以上铜色。

### 我的与种子入口

- [x] 底部导航增加第三项“我的”，只在三个一级页面显示。
- [x] 个人中心展示累计打卡天数、累计完成局数、全勤月份和当前连续天数。
- [x] 数独难度选择页提供“按种子进入”、粘贴/清空友好行为和进入按钮。
- [x] 种子卡覆盖空输入、合法种子、非法种子和长文本状态；个人中心只保留跨游戏统计。

## 非目标

- 不增加账号、头像上传、云同步、排行榜、好友或分享服务器。
- 不为尚未上线的游戏创建假任务。
- 不保证未来生成器算法升级后旧的无版本编号永久可复现；若生成规则需要破坏性升级，必须同步升级编号格式并保留旧解析器。
- 不复制 Pokémon 的 Electron 加密分表或复杂 profile 字段；只采用版本 DTO、统一 normalize/migrate 和平台 adapter 的边界。

## 依赖边界与状态模型

- `packages/sudoku-core`：编号格式、严格解析与 seed 复现，保持纯 TypeScript。
- `packages/game-core`：`GameId` 与已上线游戏目录，是每日任务清单的事实源。
- `apps/web/src/features/activity/`：按日期、游戏类型记录完成信息，派生每日任务、连续天数和月度全勤。
- `apps/web/src/features/profile/`：个人中心页面，只展示活动记录派生的跨游戏统计。
- `apps/web/src/games/sudoku/components/`：种子输入和替换存档的二次确认，不直接访问浏览器 API。
- `apps/web/src/platform/clipboard.ts`：剪贴板 adapter。
- `apps/web/src/platform/saveStore.ts`：继续作为存储 adapter；页面不直接读写 localStorage。

活动存档升级为 `math-game:activity:v5`：

```text
ActivityRecordV5
├── schemaVersion: 5
└── days[YYYY-MM-DD]
    ├── requiredGameIds[]
    ├── games[GameId]
    │   ├── completedGames
    │   ├── bestSeconds
    │   └── lastCompletedAt
    ├── checkIn?.recordedAt
    └── makeup?.recordedAt
```

`requiredGameIds` 固化当天实际要求的任务，避免未来新增游戏后历史打卡被追溯改写。任务游戏完成时同时写入真实 `games[GameId]` 和 `checkIn`/`makeup`；独立 pending-task v1 保存中途未完成任务的目标。v4 中没有游戏成绩的误签到会在迁移时删除，合法 v3/v2/v1 历史记录继续迁移。成功后写入 v5，旧 key 暂时保留用于回退，不再继续更新。

## 异常恢复

- v5 版本、日期、游戏 ID、打卡/补签时间或条目值非法时恢复为空记录，不从损坏 v5 静默回退旧版本。
- v2 已存在但损坏时恢复为空记录，不继续回退到陈旧 v1。
- v1 合法时确定性迁移；非法 v1 恢复为空记录。
- 剪贴板不可用或权限拒绝时显示“复制失败，请长按编号复制”，不影响结算流程。
- 种子非法时停留在数独难度选择页，不生成题目、不覆盖现有未完成存档。
- 合法种子生成失败时返回数独难度选择页并显示错误，不进入半初始化游戏。

## 验收方法

- [x] 单元测试覆盖编号大小写/空格、非法难度、非法字符、超范围 seed 和同编号题面一致。
- [x] 单元测试覆盖 v1/v2/v3/v4 → v5 迁移、无游戏误签到清理、任务目标恢复和普通游戏不自动签到。
- [x] 单元测试覆盖完成今日/补签任务后签到、日期边界，以及金银铜奖杯阈值。
- [x] 真实浏览器完成一局后点击复制，确认复制成功态写入显示的完整编号。
- [x] 在数独难度选择页输入该种子并进入，确认题面 ID、难度和棋盘与原题一致。
- [x] 真实浏览器确认“首页 / 日历 / 我的”导航、每日任务状态和个人统计。
- [x] 验证 `320 × 640`、常见手机尺寸和横屏居中布局无裁切。
- [x] 运行 `pnpm typecheck`、`pnpm build`、`pnpm test` 与 `git diff --check`。

## 完成标准

复制和种子复现构成可用闭环；活动记录按游戏类型建模且旧数据无损迁移；日历只把全部任务完成的日期视为打卡；“我的”页面与第三个导航可用；错误状态明确；测试、真实浏览器路径、布局和文档全部验收通过。
