# 算术填字 MVP 计划

## 状态

阶段功能已经完成并归档。技术 ID 为 `crossmath`，对外名称为“算术填字”。`320×640`、更多常见手机宽度和横屏的专项视觉验收保留为后续优化项，不阻塞本阶段收口。

## 已确认的产品规则

- [x] 玩家先点击数字或符号卡牌，再点击同类型空格；不支持拖动。
- [x] 卡牌只能使用一次，允许数值相同但身份不同的重复牌。
- [x] 点击已放置卡牌可拿回牌池，选中另一张卡牌可替换。
- [x] 固定数字、玩家输入、变量、空格和禁用格使用不同的形状与高对比配色。
- [x] 数字格和符号格都能成为填写目标，但数字牌与符号牌不能跨类型误放。
- [x] 填图过程中不提前判错；所有卡牌放完后统一检查。
- [x] 若检查失败，冲突支流中的玩家卡牌自动退回牌池，其他已成立支流保留。
- [x] 地图只要求解数量 `>= 1`，允许一道题存在多个数学上正确的完整解法。
- [x] 所有卡牌用完且全部关系成立后才完成关卡。

## 统一地图生成：支流路径算法

四档难度共用同一套地图生成器，不再使用方阵模板。

1. `generateEquationSystem`：按难度生成一批长度不一的 n 元一次等式/不等式模板。每条模板保存完整 token 顺序和唯一判定符；数字位置此时是未知节点或系数，还没有为了某个答案预填最终数字。
2. `selectJunctions`：只从未知节点中选择连接候选，形成关系网络；不决定棋盘坐标，也不参与数值求解。
3. `buildConstraintMap`：把连接网络作为不可反转的 token 带横向或纵向嵌入 `14×14` 地图。选中的交叉数字格通过并查集合并；放不下时换方向、换衔接点或放弃该布局，但不能修改方程迁就空间。
4. `solveConstraintMap`：对最终地图的 `=`、`> < ≥ ≤` 约束统一求解。`× ÷` 至少一侧必须是系数，禁止未知量相乘或用未知量作除数；使用精确有理数和有限难度域传播候选，从全局可行域中按 seed 选择一组数值，无可行值时回到前序算法重试。
5. 求值后按实际格子定位每个判定符，并以它为中点分别解析左/上侧与右/下侧；`+ − × ÷` 操作数严格保持 token 与版面顺序，任何运算都不倒读或交换。局部关系不成立立即回溯，不留到终盘补救。
6. 完整地图仍由独立反解析器重新扫描所有判定符；通过后才挖去部分数字和符号。挖空后的题面必须接受坍缩时保留的完整解作为构造性 witness；独立求解器测试继续验证至少一解与允许多解。
7. 路线选择、候选坍缩和整图重试都有固定上限；同一难度和 seed 始终复现相同地图，不会无限搜索。

| 难度 | 年级建议 | 支流数 | 最少汇聚 | 数字空格 | 符号空格 | 内容 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 入门 | 一年级起步 | 9 | 1 | 7 | 2 | 20 以内加减，只使用等号 |
| 简单 | 一至三年级 | 12 | 2 | 10 | 3 | 百以内四则与大小关系 |
| 普通 | 三至五年级 | 14 | 2 | 12 | 4 | 整数/有限小数为主，固定约 4 个分数格，比较关系控制为 4 条 |
| 困难 | 五至六年级 | 16 | 3 | 12 + 3 个变量值 | 6 | 共享变量 `a、b、c` 与多支流推导，比较关系控制为 5 条 |

困难档使用 `a、b、c`，避开 `x` 与乘号 `×` 的视觉混淆。同一变量在地图中出现两次，变量值通过独立答案格填写。
普通和困难都以等式为主体，比较关系不超过总支流约三分之一；难度差异主要由小数、分数、共享变量和关系网络规模承担，不通过密集堆叠 `> < ≥ ≤` 制造。

## 数学语义

- [x] 核心层使用规范化有理数，不使用浮点近似判断。
- [x] 支持 `+ − × ÷` 与 `= > < ≥ ≤`，除法禁止除以零。
- [x] 入门结果不出现负数；普通档主体使用整数和有限小数，只在两条叶子支流放置共 4 个分数格，避免分数沿交叉点扩散到全图。
- [x] 变量在整张地图中全局一致。
- [x] 等价分数规范化，`1/2` 与 `2/4` 按同一数值处理。
- [x] 解存在性、玩家完成判定和关系错误反馈均使用同一套精确求值逻辑。

## 核心与会话结构

```text
packages/crossmath-core/src/
├── types.ts       地图格、卡牌、关系、变量和会话值类型
├── rational.ts    精确有理数
├── evaluator.ts   表达式和关系求值
├── solver.ts      有限卡牌搜索、零解/一解/多解计数
├── generator.ts   seed、支流 DFS、赋值、隐藏和有解检查
└── hints.ts       可验证的结构化数字提示

apps/web/src/games/crossmath/
├── pages/          难度、生成、游戏和结算页
├── components/     地图、卡牌池、变量区、工具栏和提示弹窗
└── state/          reducer、完成检查和版本化存档恢复
```

- [x] 核心包不依赖 React、DOM、存储或数独核心。
- [x] 标准答案、题面和玩家 placements 分离；React 不读取答案逐格判错。
- [x] reducer 覆盖选择、放置、移动、替换、拿回、撤销、清空、暂停、计时和提示。
- [x] 未完成游戏自动保存；刷新、退出和恢复后保留摆放、时间和变量值。
- [x] 存档使用版本化 schema，非法牌、目标、重复牌或跨类型 placement 会被拒绝。
- [x] 题号格式为 `cross-<s|e|n|h>-<seed-base36>`，非法编号不会覆盖现有存档。

## UI 与应用接入

- [x] 四档统一显示 `14×14` 地图；禁用格切出随机分叉轮廓，不再显示三个方块模板。
- [x] 固定格为暖黄，空格为白底青色虚线，玩家输入为深青白字，变量为紫色。
- [x] 已放卡牌同时显示降低对比、虚线、对勾和“已放”，不只依靠颜色。
- [x] 支持按钮键盘操作、ARIA 名称、空格暂停、`Ctrl/Cmd+Z` 撤销和 `Esc` 关闭提示。
- [x] 提供撤销、清空、暂停、提示和无倒计时计时。
- [x] 注册首页入口、普通成绩、题号进入和未完成游戏恢复。
- [x] 接入今日任务、历史补签和活动统计；数独与算术填字任选一项完整完成即可签到。
- [x] 历史日期继续使用记录中固化的 `requiredGameIds`，不随目录变化回写。

## 异常恢复

- [x] seed 或生成失败进入明确错误页，不进入半初始化游戏。
- [x] 路线和整图生成均有固定尝试上限。
- [x] 损坏或未知版本存档拒绝恢复，并允许安全开始新局。
- [x] 未完成退出、暂停和恢复不会计入每日任务。
- [x] 填满后的错误关系保留提示边框，并只退回冲突支流卡牌。
- [x] 局部合法但令剩余牌无解时，提示可搬移错误位置上的已用牌。

## 非目标

- 拖动卡牌。
- 任意表达式编辑器和用户自制关卡。
- 乘方、根式、无理数或负数答案。
- 在线题库、账号、排行榜、广告、内购和多人竞赛。
- 为本游戏单独建立第二套日历或统计系统。

## 完成标准

四档均使用可复现的 14×14 支流地图并保证至少一解；多解可以正常完成；数字和符号卡牌交互可靠；填满错误时只退回冲突支流；会话可恢复；普通成绩、今日任务和补签共用现有活动事实源；自动化与真实浏览器验收全部通过。
