# Activity Calendar Plan

> 状态：已完成并归档。2026-08-07 起由 `plan/current/profile-daily-challenge-plan.md` 的按游戏每日任务模型取代；本文保留为首次日历打卡实现记录。

## 目标

为 MathGame 增加跨游戏、离线可用的轻量练习记录：完成一局后标记玩家本地日期，同日累计完成局数；自然月每天至少完成一局时，在该月份点亮金色全勤奖杯。

## 范围

- [x] 首页与日历两个一级页面使用底部导航切换。
- [x] 只有完整结束一局才计入记录，未完成退出、暂停和恢复不计入。
- [x] 日期按玩家本地时区保存为 `YYYY-MM-DD`。
- [x] 同一天累计完成局数，并保存当天最佳用时和最近完成时间。
- [x] 日历默认当前月，可向前查看历史月份，不可进入未来月份。
- [x] 完成日期同时使用颜色、对勾和局数标记；当天有独立边框。
- [x] 自然月每一天都有完成记录后切换为金色全勤奖杯。
- [x] 显示当前连续完成天数、当月完成天数与总局数。

## 非目标

- 不增加账号、云同步、后端、排行榜或社交分享。
- 不增加金币、签到补卡、奖励领取或运营任务。
- 不把活动记录下沉到数独核心；后续其他游戏在应用层复用同一完成事件。
- 不允许手动打卡，只有真实完成游戏才记录。

## 依赖边界与状态模型

活动领域逻辑位于 `apps/web/src/features/activity/activity.ts`，只处理记录、恢复和派生统计；日历页面位于同一 feature，底部导航是跨游戏共享组件。`App.tsx` 在游戏完成回调中编排写入，所有浏览器存储仍经 `platform/saveStore.ts` 访问。

本地存储 key 为 `math-game:activity:v1`，结构包含 `schemaVersion: 1` 和按日期索引的 `days`。每日条目包含 `completedGames`、`bestSeconds` 和 `lastCompletedAt`。月度全勤按目标年月的真实日数逐日检查，不用固定 30/31 天。

## 异常恢复

- 版本不支持、结构非法、日期不存在或数值越界时，整体恢复为空活动记录。
- 空记录显示 0 天、0 局和未点亮奖杯，不阻塞首页或开始游戏。
- 未来月份入口禁用；历史月份没有记录时显示正常空月，不伪造日期状态。
- 存储写入失败不影响结算页跳转；当前会话仍立即更新内存中的日历状态。

## 验收方法

- [x] 单元测试覆盖同日多局、最佳用时、闰年 2 月、连续天数和非法数据。
- [x] 真实浏览器完成一整局，确认当天出现完成标记和 `1 局`统计。
- [x] 验证同日 `2 局`显示和月总局数累加。
- [x] 验证自然月全勤后出现 `.monthly-trophy--complete` 金色奖杯。
- [x] 验证上月可进入、返回当前月后下月按钮禁用。
- [x] 在 `320 × 640` 逻辑视口检查空状态、打卡状态和全勤状态无裁切。
- [x] 运行 `pnpm typecheck`、`pnpm build`、`pnpm test` 与 `git diff --check`。

## 完成标准

记录只在完整结算时产生；同日局数和自然月全勤计算正确；非法数据可恢复；首页、日历和游戏页面之间不互相遮挡；图标与既有视觉语言统一；相关单元测试、浏览器路径、全量构建检查和文档同步全部通过。
